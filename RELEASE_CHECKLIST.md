# Pre-Pilot Release Checklist

Complete every item on this list before deploying Engagement Harness to a client environment for the first time.

## Build and Tests

- [ ] `pnpm build` completes with zero TypeScript errors across all packages
- [ ] `pnpm test` passes — all 300+ tests pass with no failures, no skips, and no timeouts
- [ ] No `it.skip` or `it.todo` calls remain in any test file
- [ ] No stray `console.log` calls in production source code (only `console.warn` via chalk in orchestrator and router is acceptable)

## CLI

- [ ] All 11 CLI commands have help text (`--help` prints a non-empty description for each: `init`, `doctor`, `review`, `report latest`, `report run`, `report list`, `config validate`, `agents list`, `models list`, `models validate`, `ci templates`, `eval`, `feedback import`, `remediate`)
- [ ] `engagement-harness --version` prints the current version string

## Configuration

- [ ] `engagement-harness config validate` exits 0 on a real client repository with a valid config file
- [ ] `engagement-harness doctor` exits 0 on a real client repository (all environment checks pass)
- [ ] No live providers appear in the default config — all agents route to `mock` when no `models` overrides are set

## Secrets and Security

- [ ] No test API keys, tokens, or credentials are present in any tracked file (search for `AKIA`, `ghp_`, `sk-`, `Bearer`, `PASSWORD=`, `SECRET=`)
- [ ] Secret redaction tested on real client diffs — run `review` against a sanitized diff containing known-format secrets and verify `[REDACTED_SECRET]` appears in place of each secret in `report.json`
- [ ] No `.engagement-harness/reports/` directories are committed to the repository

## Eval

- [ ] `engagement-harness eval` runs all 6 fixture cases without error
- [ ] Eval precision is >= 0.8 across all fixture cases
- [ ] Eval recall is >= 0.8 across all fixture cases

## CI Integration

- [ ] `engagement-harness review --ci` exits with code 0 when `ci.blockOnPolicy` is `false` (the default)
- [ ] `engagement-harness review --ci` produces all 3 report formats (`report.json`, `report.md`, `report.html`) in `reports.outputDir`
- [ ] CI template generated by `engagement-harness ci templates --platform github` triggers correctly on a pull request in a fork repository (GitHub Actions workflow runs and completes without error)
- [ ] Review `--ci` produces a non-zero exit code when `ci.blockOnPolicy: true` and the policy engine returns `block`

## Reports

- [ ] `report.json` is valid JSON and parses against the expected `PipelineResult` shape
- [ ] `report.md` renders correctly in a Markdown viewer with no broken syntax
- [ ] `report.html` opens in a browser with no missing assets (self-contained single file)
- [ ] `engagement-harness report latest` prints the most recent report to stdout without error
- [ ] `engagement-harness report list` lists run IDs with timestamps

## ALM

- [ ] `alm.platform` defaults to `"none"` — no ALM calls are made in the default config
- [ ] `ci.postComments` defaults to `false` — no PR comments are posted without explicit opt-in

## Installation

- [ ] README install instructions tested on a clean machine with no prior Engagement Harness installation — `pnpm install`, `pnpm build`, and `engagement-harness --version` all succeed from a fresh checkout
